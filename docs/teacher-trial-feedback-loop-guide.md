# 教师试用说明：学生反馈驱动的课件优化闭环

本说明用于阶段53小规模试用。试用目标不是评估完整学情系统，而是验证一条闭环：学生看课件后反馈没懂，老师据此优化课件、发布新版，并布置一次复习。

## 适用范围

- 学科范围：当前优先验证中文初中数学。
- 主线字段：`knowledge_point_code`。
- 适合试用的课件：已经由老师发布到学生端的结构化课件。
- 不包含：完整班级系统、班级码、批量导入、成绩统计、PPT/视频导出、平台资源市场。

## 教师操作流程

1. 发布一份课件给学生。
   - 进入教师课件详情页。
   - 确认内容可用于课堂或课后学习。
   - 点击发布到学生端。

2. 让学生学习课件并提交反馈。
   - 学生进入课件学习页。
   - 如果没有看懂，选择“没看懂”。
   - 如果希望老师再讲，勾选“希望老师再讲一次”。
   - 学生可以写一句具体说明，例如“移项为什么要变号没看懂”。

3. 教师查看学习数据。
   - 进入 `/teacher/analytics`。
   - 查看“学生请求老师再讲”区域。
   - 重点看学生、知识点、学生说明和跟进状态。

4. 教师处理反馈。
   - 点击“去优化课件”进入课件详情页。
   - 系统会把学生反馈整理成优化要求。
   - 老师可编辑补充要求后，再点击生成优化候选版。
   - 等待期间页面会显示生成进度提示。

5. 教师确认候选版。
   - 预览候选版。
   - 若可用，点击采用新版。
   - 采用后再发布给学生。
   - 未采用前，学生端正式课件不会被覆盖。

6. 教师布置复习。
   - 在学习数据页从反馈列表或弱项知识点处点击布置复习。
   - 选择到期日。
   - 学生会在 `/student/review` 看到“老师布置复习”。

## 试用观察点

- 学生反馈是否足够具体，能否帮助老师定位课件问题。
- 教师是否能理解“候选版未采用前不影响学生端”的边界。
- 生成候选版耗时是否可接受。
- 跟进状态是否能帮助老师避免重复处理。
- 复习任务是否能承接“老师再讲一次”的后续动作。

## 明确边界

- 学生反馈只作为“待巩固信号”，不是完整能力诊断。
- 掌握度规则是轻量提醒，不应直接替代老师判断。
- 资源推荐暂不使用学生反馈影响平台排序。
- `teacher_review` 只是复习布置 MVP，不是完整作业系统。
- AI 生成内容必须由老师预览确认后再采用和发布。

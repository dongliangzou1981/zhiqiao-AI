# K12 教育知识库基础模块

## 建设目标

K12 教育知识库用于把知桥 AI 的教案、课件、学生答疑、练习、复习和学情信号统一到稳定的课程知识结构上。第一阶段目标不是导入全量外部知识库，而是先建立可扩展的数据模型，并用初中数学小样本验证接入方式。

## 为什么以国家课程标准为主线

教学内容不能由模型自由组织。课程标准定义了学段目标、内容边界、核心素养和评价方向，是后续生成教案、课件、练习与复习建议的上层约束。AI 可以辅助生成内容，但知识点范围、学习目标、重点难点和教学顺序必须由课程标准与教材体系限定。

## 小学、初中、高中如何扩展

知识库通过 `school_stages`、`subjects`、`grades`、`textbook_versions`、`textbook_books`、`chapters` 和 `knowledge_points` 分层扩展：

- 小学、初中、高中先作为学段主数据。
- 每个学段下挂学科，例如初中数学、小学语文、高中物理。
- 学科下再挂教材版本、年级册别和章节。
- 知识点通过 `knowledge_point_relations` 建立前置、后继、相关、易混淆、同方法、同题型等关系。

## 为什么第一阶段只做初中数学

当前项目已有初中数学教案、课件、学生复习和反馈闭环。先做初中数学小样本，可以用最小数据量验证“课程标准 -> 教材章节 -> 知识点 -> 生成上下文 -> 学生反馈”的闭环，避免一次性铺开小学、初中、高中全学科后难以验收内容质量。

## 数据表说明

- `curriculum_standards`：课程标准版本，例如“义务教育课程标准 2022年版”。
- `school_stages`：小学、初中、高中。
- `subjects`：学段下的学科。
- `grades`：一年级到高三。
- `textbook_versions`：教材版本，例如人教版。
- `textbook_books`：教材册别，例如七年级上册。
- `chapters`：教材单元和章节。
- `knowledge_points`：知识点主表。现有表继续保留，同时新增课程标准、章节、学习目标、重点难点、难度和重要度字段。
- `knowledge_point_relations`：知识点关系，包括 `prerequisite`、`next`、`related`、`includes`、`part_of`、`commonly_confused_with`、`same_method`、`same_question_type`。
- `common_mistakes`：知识点常见错误和纠正策略。
- `question_bank`：题目主表。
- `question_knowledge_points`：题目与知识点的多对多关系。
- `teaching_resources`：教学资源，保留来源和版权说明。
- `student_weakness_records`：学生薄弱点记录，后续可由练习、反馈和复习结果汇总。

## 现有知桥功能接入点

- 教案生成：`/api/lesson-plan` 会按知识点编码读取 K12 知识库上下文，把学习目标、教学重点、教学难点和常见错误注入生成上下文。
- 学生答疑：`/api/student-qa` 预留简单关键词匹配。如果学生问题命中示例知识点名称，会把该知识点、常见错误和相关知识点注入答疑上下文。
- 教师知识库页面：当前仍保留本地初中数学结构浏览，后续可逐步切换到 Supabase 查询函数。
- 课件、复习和学情：继续使用现有 `knowledge_point_code` 作为主线，后续可用 `knowledge_points.id` 和关系图增强推荐与复习路径。

## 未来外部知识库接入

第一阶段不直接接入外部大规模开源库，也不爬取国家智慧教育平台。后续只在数据模型稳定后做受控导入：

- 清华 EDUKG / OpenEduKG：可映射到知识点、关系和实体解释。
- OpenKG：可作为通用知识图谱补充，但需要人工筛选教育相关内容。
- Math23K、APE210K、CMM-Math：可作为数学题库或应用题样本来源，需保留来源、版权说明和题目清洗流程。

外部数据导入必须经过：来源确认、字段映射、去重、质量抽检、版权记录和小范围试用。

## 当前限制

- 只提供初中数学七年级上册小样本，不代表完整学科覆盖。
- 知识点关系和常见错误是人工整理的小样本，不能替代完整教研审核。
- 学生答疑只做简单知识点名称匹配，不做向量检索或复杂语义匹配。
- AI 输出仍需老师审核，课程标准上下文只能减少偏题风险，不能自动保证数学内容完全正确。
- 迁移没有自动抓取外部平台或国家智慧教育平台内容。

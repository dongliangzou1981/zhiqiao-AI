# 风险与差异记录

## P2 阶段33后续风险

- 内容质量分是规则检查结果，不等于真实课堂教学效果；最终仍需要老师人工验收。
- 当前质量检查主要覆盖结构完整性、知识点追踪、推导完整、练习解析和投屏约束，不能自动判断所有数学内容是否绝对正确。
- `lib/courseware-quality.test.ts` 已加入 TypeScript 检查；阶段45已补齐 `npm run typecheck`、`npm test` 和 `npm run test:courseware`，后续风险转为是否接入 CI。
- `asset_metadata.content_quality` 复用现有 JSON 元数据，不新增数据库字段；如果后续需要按质量分筛选资源库，可能需要独立字段或索引。
- 旧课件不会自动重新生成，只能在详情页即时评估或重新生成后写入新质量报告。
- `data-layout` 已写入 Prompt 和规则，但不同模型遵循程度仍需通过真实生成继续观察。
- 当前样板课件质量分 93，仍提示“幻灯片版式有变化”可优化，说明旧课件在视觉丰富度上还未完全达标。

## P2 阶段31后续风险

- 当前只对已有内置高质量分镜的样板知识点实现低质量 AI 分镜回退；更多知识点仍需要逐步沉淀内置模板或更强的生成规则。
- `prompts/courseware-json.md` 已禁止泛化分镜文案，但不同模型的遵循程度仍需通过真实生成继续观察。
- 动态课件播放器仍是 HTML 互动 MVP，已改善步骤完整性和回看准确性，但还不是视频级自动讲解或成熟 PPTX 导出。
- 后续如果接入 ofox/ChatGPT 等模型，应继续以“基础知识讲清楚、学生能跟上”为验收标准，而不是只看视觉效果。

## P2 阶段30后续风险

- 本阶段只做了“控件存在”和“选项生成”的浏览器验证，未在浏览器中执行保存，以避免改动当前样本课件数据。保存链路仍沿用 P2 阶段9已验证的 `PUT /api/courseware/[id]`。
- `lesson-plan` / `student-qa` Prompt 双来源技术债仍存在，虽已降低风险但仍建议在后续阶段继续收敛。
- 动态课件仍处于 HTML 互动 MVP，尚未达到真正视频级或成熟幻灯片级的自然演化效果。

- P2 阶段1已完成；P2 阶段2 AI 课件生成 MVP 也已完成真实浏览器点击验证。
- 当前验证覆盖页面 HTTP 访问、API 调用、DeepSeek 调用、数据库写入、基础 RLS、真实浏览器点击与 P0/P1 回归。
- `lesson-plan` / `student-qa` 仍有 Prompt 双来源技术债，文件模板与代码内 Prompt 后续可能分叉。
- 教案历史仍使用 localStorage，跨设备、跨浏览器和登录态下不可共享。
- 旧路线曾建议下一步进入学情分析；最新产品判断已调整为先做教师端完整化，再做学生端完整化、两端数据整合，最后做学情分析。
- 学情分析当前不应提前开发，因为缺少学生练习、日/周复习、课堂互动和知识点掌握记录。
- 课件、素材、示例、练习如果不关联 `knowledge_point_code`，后续会难以支持学生弱项定位和班级学情分析。
- 对标飞象老师和同类产品时，不能只追求炫酷动画或复杂三维；必须筛选真正能帮助老师讲清基础知识、学生掌握基础知识的能力。
- 当前不应一口气做多学科；先用中文初中数学跑通闭环。
- 多语种扩展后置；近期只做中文版本。
- AI 课件生成 MVP 已完成教师登录态真实点击生成验证；仍需后续对更多知识点做内容质量评测。
- 课件历史已完成，但暂不支持删除、重命名、收藏、搜索、导出或分享。
- 结构化课件 JSON 已完成，但当前仍依赖 AI 输出质量，后续需要在学生端复用时继续收敛字段稳定性。
- P2 阶段4学生端知识点学习闭环只读 MVP 已完成；该阶段本身不记录学生作答，后续已由 P2 阶段5/6补上练习记录与复习任务。
- P2 阶段4收尾已完成课件发布/取消发布 MVP，`coursewares_student_select_learning` 已收紧为学生只能读取 `is_published = true` 且 `content_json is not null` 的课件资源。
- 当前发布范围仍是“发布给学生端全体可见”，还没有班级、学生组或单个学生范围控制；后续需要补 `class_id`、班级成员关系或只暴露学习字段的 view。
- P2 阶段5基础练习与掌握记录 MVP 已完成，但当前判定方式只是答案标准化后的精确匹配，不支持复杂数学等价、步骤评分或开放题评价。
- `student_practice_records` 当前已支持教师只读查看已关联学生记录，但仍没有完整班级弱项聚合。
- P2 阶段6日/周复习系统 MVP 已完成，但当前只是简单规则：答错次日复习，所有作答一周回顾。
- P2 阶段7两端数据整合最小版已完成，教师端已能只读查看已关联学生的练习记录、复习任务和知识点维度统计。
- `teacher_student_links` 当前只提供数据范围控制，尚无教师端添加、移除、导入学生的管理界面。
- `/teacher/analytics` 当前是学习数据视图，不是完整学情分析；仍不生成自动诊断、教学建议或班级弱项报告。
- 当前还没有掌握度模型，不计算连续正确、遗忘曲线、题目难度权重或知识点熟练度。
- 当前只有测试教师与测试学生建立了验证关联；正式使用前需要补班级/学生范围管理或后台导入流程。
- 当前已验证 `J-MATH-RJ-71-01-03` 数轴和 `J-MATH-RJ-71-05-03` 一元一次方程的解法两个样板点。
- 原 `D:\Codex\Projects\Active\知桥AI` 为空仓库，已备份或待确认。

## P2 阶段14补充风险：课件资产化与模型成本

- 当前 `asset_metadata` 先存放在 `coursewares.content_json` 内，尚未拆成正式数据库列；优点是不会破坏现有表结构，缺点是后续筛选/审核/统计需要迁移为结构化字段或视图。
- 旧课件没有模型来源记录，只能展示为“旧课件 / 未记录模型”；新生成课件才会有 provider/model 记录。
- 发布课件当前代表“老师确认并班级可见”，还不等于平台审核通过；后续平台精选、公开资源库、版权审核必须单独设计。
- 学生端目前仍默认按知识点取一个可用课件，尚未提供“老师课件 / 平台精选课件 / 官方基础资源”的选择器。
- 模型选择已经具备接口层能力，但不同模型输出稳定性、JSON 兼容性、价格控制和额度策略仍需持续验证。
- 版权和教育知识库接入仍未开始；任何外部资源进入平台精选前都需要记录来源、授权状态和审核流程。

## P2 阶段15剩余风险：课件资源库与多课件选择

- 多课件排序目前仍较简单：默认沿用 `created_at desc`，尚未实现平台精选、教师确认、质量评分的综合排序。
